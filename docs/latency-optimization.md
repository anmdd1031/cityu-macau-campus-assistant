# Skill 查询路径优化与完整响应复测

日期：2026-10-28–29（北京时间）。结论：已减少部分工具调用，并完成确定性查询入口；**尚未证明通用 Agent 的完整响应有显著提速**。导师姓名传递修复有一个最终答案通过的样本，第二次调用受额度限制中断，不能宣称稳定解决。

## 本轮保留的改动

- 地图标识、公开邮箱和明确届次的 FDS 学费可由程序直接返回答案、适用范围及来源。普通 Markdown 读取仍可使用。
- `mentors` 一次返回候选和所需规则，避免重复读取；`evidence` 返回完整原文片段及来源，减少重复包装，不用自动摘要替代证据。
- `recommend` 提供透明的字面方向初选，适用于宿主直接展示。个性化选择可由模型返回 ID 和理由，再由宿主 `finalize` 生成原文身份表格。尚未接入任何下游应用。
- 支持 CommonMark 的客户端可用 `--portable-names` 无损传递姓名。数字字符引用渲染后是原始中文，纯文本客户端应省略该参数。58 个姓名往返检查通过，表格编码前后 Markdown-it 渲染 HTML 一致。
- 专项边界原文移至按需引用文件；学校事实资料未重写。

## 测试口径

旧版为提交 `7d30eaed8eecd3280d28eda6133e41967a3686e0`。使用同一台 Windows 电脑、串行独立 `codex exec` 调用，模型为本机配置的 `gpt-6-astra`、medium 推理。计时从进程启动到完整回答结束，包含工具和模型等待，不是首字时间。题目与可复用脚本见 [run_cases.py](benchmarks/2026-10-28/run_cases.py)。

主比较强制中文文件以 JSON ASCII 转义传输；另列正常 UTF-8 提示实验，不能混算。每个阶段为独立会话，服务负载、缓存及模型路径不完全可控，样本很少。导师结果在最终答案输出后重新与本地原表核对姓名、资格、邮箱、主页，不能以模型中途自检成功替代验收。周围解释不在四列校验范围内。

初始 WebSocket 连接重试导致地图、学费分别耗时 153.70、148.91 秒，均从干净比较中排除。后续只对测试子进程使用临时 HTTP provider，未修改用户全局配置。错误的内置 provider 覆盖尝试、超时和额度失败均单独记录。

| 题目 | 干净旧版 | 中间版（final-all） | 判断 |
|---|---:|---:|---|
| B1 地图含义 | 37.34 秒，3 次命令 | 47.82 秒，2 次命令 | 调用减少，但未更快 |
| MAI 学费及新课程标签 | 37.99 秒，2 次命令 | 52.44 秒，3 次命令 | 未更快，发生额外目录读取 |
| IUSD 博士答辩条件 | 69.17 秒，2 次命令 | 63.82 秒，2 次命令 | 单次更快，不能推断稳定改善 |
| 视觉硕士导师 | 96.40 秒，7 次命令，身份通过 | 81.67 秒，4 次命令，姓名错误 | 更快样本未通过准确性验收 |

地图、费用和条件检查的样本按相应本地证据核对，具体回答保存在历史检查结果中。这三题未在最后的姓名传递版本重新执行，不代表最终版本的全量测试。

导师路径的后续实验：

| 阶段 | 完整响应秒数 | 最终身份校验 |
|---|---|---|
| 最初直接推荐（after-http） | 57.30 | 失败 |
| 要求实际草稿校验（final-mentors） | 111.69 / 121.11 | 两次失败 |
| 正常 UTF-8 提示旧版 | 142.32 | 通过 |
| 正常 UTF-8 提示推荐版 | 128.73 / 92.36 | 一次失败、一次通过 |
| 恢复候选选择并给码位提示（retained-agent） | 109.85 / 92.49 | 两次失败 |

反复出现的错误是模型把“眭相傑”抄成“睭相傑”，甚至发生在草稿校验成功之后。因此没有采用“省去校验即成功提速”的结论。最后一个有效样本比干净旧版约快 4.4%，命令数由 7 降到 4；**仅各一次，不能称显著进步或稳定准确**。

全部可用阶段的紧凑汇总见 [all-results.json](benchmarks/2026-10-28/all-results.json)。原始模型上下文、工具日志保留在本地缓存，不发布。汇总可用同目录 `summarize_results.py` 从本地日志重新生成。

## 程序直接返回的速度

每项五次独立 CLI 调用，中位数：地图 0.210 秒、邮箱 0.206 秒、学费 0.217 秒、导师字面初选 0.219 秒。见 [direct-results.json](benchmarks/2026-10-28/direct-results.json)。这只包含本地程序启动、读取与答案构造，不含请求分类、网络、模型解释或应用展示，不能与上表作为同一流程的加速比。

真正可以省掉大量等待的接入方式是：应用已知明确问题类型和必要参数时，调用对应查询并直接展示 `answer`；复杂或不明确的问题才调用模型。个性化导师推荐让模型选 ID、写理由，程序在模型之后补上身份字段。单纯安装 Skill 不会自动改变 Agent 宿主的流程。当前尚未确定用户要接入的应用，因此没有修改小程序或其他项目。

## 验证与后续

29 项单元测试覆盖原文身份、错字拒绝、版本变化、候选筛选、届次限制、地图范围、证据完整性和字符引用往返。Skill 格式检查与 Git 差异检查单独执行；它们不代表模型端到端验收。

下一步需要在目标应用接入直接展示路径，并在额度恢复后对同一批问题进行多轮完整响应对照。衡量中位数、较慢请求与最终正确率；失败样本保留，不把失败或不完整回答计为更快。本报告实验结束时，代码尚未提交或上传；后续发布状态以 GitHub 为准。

后续补充（2026-10-30）：新增应用常驻进程 `runtime/host.py`，四类已分类查询各 10 次对照，中位数从约 185–192 ms 降至 0.4–6.5 ms，两种路径完整结果一致；测试总数增至 33。详情见[接入说明](host-integration.md)。这解决本地重复启动开销，未重新进行模型完整回答测速，也未接入下游应用。

## 研究依据与采用范围

- [Adaptive-RAG，NAACL 2024](https://aclanthology.org/2024.naacl-long.389/)：按问题复杂度选择路径。本轮只采用明确范围的轻量分流，未复现其分类模型或论文结果。
- [LLMCompiler，ICML 2024](https://proceedings.mlr.press/v235/kim24y.html)：减少串行工具往返。本轮采用批量返回候选和规则，未引入框架。
- [LongLLMLingua，ACL 2024](https://aclanthology.org/2024.acl-long.91/)：减少无关输入。本轮采用按需加载与去除重复包装，保留原文，未压缩学校事实。
- [CommonMark 字符引用规范](https://spec.commonmark.org/0.31.2/#entity-and-numeric-character-references)：用于姓名的无损 Markdown 传输，不是检索加速算法。

论文中的加速比例不作为本项目的测量结果。
