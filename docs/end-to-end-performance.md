## 为什么仍需几十秒

实际调用轨迹表明，仅两次学费题使用了 `read_sections.py`；其余六次仍以自写 Python 直接读取 Markdown。多次重复加载主 Skill，部分调用还搜索了宿主的 MEMORY.md。导师题分别执行 7 次和 5 次命令，累计工具输出约 18.6 万和 14.3 万字符。

这表明新读取器的可用性修复并未自动转化为宿主稳定采用它。测试提示沿用了 ASCII JSON 输出要求，这也会膨胀文本并影响工具选择；以上是当前指定提示和宿主环境下的实际结果，不能视为普通对话的唯一性能表现。未对模型思考、服务排队等阶段分别计时，不能给出各阶段耗时占比。

下一步建议先做两项针对性改进，再用相同问题复测：

1. 将快速读取入口接入宿主的结构化工具，或缩短并明确首次加载规则后的读取流程，减少重复规则与资料读取。需要在实际宿主验证采用率，不能只改 Skill 后假定已生效。
2. 对教师姓名、邮箱和主页采用结构化字段回填或最终确定性比对；仅提示“照原文”在这两次测试中不足以保证正确。

本轮仅复测和记录，未继续修改 Skill 或读取器。此前约 0.20 秒是本地工具启动及返回原文的开销，不是本轮完整回答时间。
