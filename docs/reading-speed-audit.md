# 全库读取速度测试（2026-10-22）

本次测试当前工作区的可选 `runtime/read_sections.py`，覆盖 26 份启用 Markdown 资料、1,857 个标题章节和主路由表的 25 条文件组合。停用的 `mentors/fds_papers.md` 不参与读取。全体资料包含知识文件及 3 份新增执行说明，不是 26 个学院。

**结论：本地读取本身很快，当前更明显的问题是标题歧义和输出范围。不能将本结果称为“所有自然语言问题都通过”，也不能外推为模型完整回答速度。**

## 方法与范围

- 环境：Windows 11，Python 3.13.14；测试当前未提交工作区，不代表远程主线或下游固定快照。
- 每个标题以完整标题选择读取 3 次，共 5,571 次章节调用；计时包括读取、解析、哈希、片段拼接和 UTF-8 JSON 编码，不含 Python 启动与模型处理。未清空操作系统缓存，属于常规重复读取，不能称为冷磁盘测试。
- 每份文件分别测目录、最大可成功叶章节的 UTF-8 CLI、同章节 ASCII CLI，各启动独立 Python 3 次；另对 25 条路由文件组合各测 3 次，共 309 次 CLI 调用。最大叶章节是确定性的压力样本，不代表该路由问题的最佳语义选段。
- 路由组合读取各目标文件的样本章节；含条件追加文件也一并计入。泛指“各学院”的路由展开为全部 12 份学院/项目文件。导师组合补充新增匹配规则。地图、文化及正文中额外提到的章节由全文件/全章节遍历覆盖。
- 成功内容逐片段与原文行范围比对，测试前后所有资料 SHA-256 一致。未修改知识内容、读取器或模型配置，未联网、未执行真实模型问答、未验证自然语言路由与事实准确性。
- 只对成功读取统计速度；标题歧义及超限返回单独计数。P95 使用 nearest-rank，基于各案例三次耗时的中位数分布，不是生产流量 P95。

## 发现与改进优先级

1. **优先解决标题歧义。** 270 个章节分布于导师官网证据（174）、FIAD（57）、FHSS（20）、餐饮（7）、FITM（6）、IROPC（4）及 FOB（2）。相同标题位于不同上级范围，单靠完整标题无法唯一选择。逐项检查确认 270 个都可用唯一上级章节在默认预算内读取，说明资料仍可取得；但额外目录查询和扩大输入会增加 Agent 开销。建议支持“文件哈希＋行号”或完整标题路径，不建议直接取第一个同名标题。
2. **保留按章节读取。** 2 个超限案例为新生指南顶层章节（101,728 字符）与导师官网证据顶层章节（198,816 字符）。这是避免整文件输出的预期限制；应按问题选子章节，不能通过全局提高上限解决。
3. **合并必要读取，减少工具往返。** 本地处理约毫秒级，独立启动约 0.2 秒，优先批量读取同一问题所需证据。即使省去启动耗时，也不能保证模型回答按同比例加速。
4. **ASCII 仅作乱码回退。** 本轮样本的 ASCII JSON 字节数约为 UTF-8 的 1.25–1.79 倍；这不是 tokenizer 的 token 倍率，不应在中文传输正常时默认使用。
5. **再测模型端到端。** 需要真实问题、答案完整性与来源评分、工具调用轨迹及多次重复。本次没有新发起模型调用，不能以此前额度耗尽的失败时间作为速度依据。

本轮仅测试和记录，未自动修改以上发现的问题。
