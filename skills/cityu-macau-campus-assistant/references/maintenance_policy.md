# 联网与维护执行规则

进行联网核验或维护前读取；离线问答无需加载。以下规则保持原文。

## 联网核验与抓取约束

- 日常问答与导师匹配不依赖维护脚本。`scripts/` 仅留在维护者本地，不随 GitHub 当前版本发布；下述爬虫专用约束仅在维护者明确进行本地维护且工具存在时适用。普通安装缺少脚本不算故障，不要求用户安装 Python 或从历史提交恢复脚本。
- 逐个 URL 串行请求，禁止线程池、异步并发、并行工具调用或同时抓取多个官方页面。
- 使用项目官网爬虫时，必须复用现有状态目录；其单用户全局操作系统排他锁会跨仓库副本和状态目录阻止第二个爬虫或最终审计，同时持久化最近请求时间。锁被占用时不得换状态目录、删除锁文件或另启进程绕过。
- 同一官方站点的两次请求启动时间至少间隔 1 秒；批量检查优先去重 URL，避免在同一轮重复下载。恢复进程时也必须继承全局锁和状态数据库中的上一次请求启动时间，不能以重启进程缩短间隔。
- 使用学校官网爬虫时，每个 HTTP 重定向都必须作为独立、限速后的请求处理；只允许继续访问 `cityu.edu.mo` 及其子域，站外或无效跳转必须记录失败而非跟随。排名核验使用独立的发布机构页面检索，不扩大学校爬虫范围，同样遵守串行与站点访问限制。
- 遇到 HTTP 403 立即停止该页面的自动重试；遇到 HTTP 429 按 `Retry-After` 延期，未提供时至少等待 5 秒。延期 URL 在到期前不得被普通重试重置或抢先访问；不得更换身份、代理或 User-Agent 绕过限制。
- HTTP 429 与 `robots.txt` 暂时不可用分别受有界重试预算约束；达到预算的 robots 受阻 URL 必须保留为 `robots_unavailable`，并继续阻止最终完整性验证。只有冷却期届满后的显式 `--retry-errors` 才可重开该主机，普通恢复不得提前重试。
- 先抓取中文列表页和中文详情页；只有中文页缺少回答所需字段时，才串行读取英文页补充。
- 页面访问失败时使用最近一次已核验的本地资料并标明核验日期，不得把抓取失败解释为页面、课程或人员已经删除。
- 每个 reference 如经完整逐条审计或发生实质内容更新，必须在页首分别维护 `信息更新时间` 与 `最近审计时间`，统一按北京时间（`Asia/Shanghai`，UTC+8）生成；不得把未通过完整性验证的机械审计写成完整人工审计。没有完整逐条审计记录时明确写“尚无完整逐条审计记录”。
- 不在页尾维护独立的文档更新时间或审计时间；表格、来源清单和正文中的逐条核验日期不受此限制。更新日志、`last_updated` 和其他日期也不得直接使用服务器、容器或操作者所在地的本地日期。
